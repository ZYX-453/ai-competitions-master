附件一 ｜ VOC 四级编码本 v1.0

用途：归因引擎的判定依据、金标准标注的操作手册、编码本演进的版本基线。冻结时间：2026-11-01。

使用方式

标注时只判 L1 + L2（L3 归因与 L4 动作由系统建议、人工确认）。原因：L1/L2 可由文本直接判定，客观性强、κ 才高；L3/L4 需要经营上下文，让模型生成更合适。这个设计决定本身就体现了对标注可靠性的理解——细分层级越多，人工一致性越差。

排他规则（消除歧义的关键）

  1. 主类优先原则：一条评论同时抱怨多个问题时，取最影响退货决策的那一类为主类。判断线索：句首句、语气最强处、是否明确提到"所以退了/所以要退"。
  2. 因果链就近原则：若 A 导致 B（"包装太薄所以压坏了"），归原因端（F1 破损，因包装问题），不归结果端。
  3. 涉实物优先：同时提到"描述不符"且"有实物质量问题"，归 P 类（实物问题更硬）。仅当无实物问题时才归 I 类。
  4. 色差三分法：说"颜色和图片不一样" → I1；说"洗后掉色" → P2；说"实物颜色不好看" → E1（审美偏好，非承诺问题）。
  5. 无效样本界定：纯表情/无意义字符/仅"好""不错"等无信息内容/纯物流好评 → X。好评中的隐晦抱怨（"就是有点小，其他都好"）算有效，归对应类。
  6. 中性描述不算问题："偏大一点，我换小一码就好了"未表达不满 → X 或按上下文判断；明确表达不满才算。

附件二 ｜ DGP 数据生成规范

用途：让模拟数据可复现、可审计。这份规范本身就是"方法严谨"的证据，务必随作品提交。

核心原则

模拟数据的价值不在于"像真的"，而在于真值已知。所以每个参数都必须：①有来源依据（文献/行业报告/合理假设）；②显式记录；③生成代码固定随机种子。参数表就是这份附件的主体。

2.2 退货率生成式

return_rate_it = logistic( a₀ + a₁·quality_endow_i + a₂·(price_i − mean_price)/sd_price + a₃·promo_t + a₄·logistics_shock_it + a₅·season_t + ε_it ) 设定（真值，冻结）： a₀ = −1.55 基线水平（对应约 18% 退货率） a₁ = −0.35 质量禀赋越高退货越低 a₂ = 0.12 价格越高退货略高 a₃ = 0.28 大促期间退货上升（冲动购买） a₄ = 0.45 物流冲击（破损/延迟） a₅ = 0.15 季节性（换季月份） ε_it ~ N(0, 0.30)

2.3 一级传导：退货率 → DSR（滞后 1–2 周）

dsr_it = 4.72 + δ_i + ψ_t − λ₁·return_rate_i,t−1 − λ₂·return_rate_i,t−2 + u_it 真值： λ₁ = 0.42 退货率每升 1pp，次周 DSR 降 0.42 分 λ₂ = 0.18 二阶滞后（部分影响延迟） δ_i ~ N(0, 0.08) SKU 固定效应 ψ_t ~ N(0, 0.04) 周固定效应（大促周额外下调） u_it ~ N(0, 0.05)

2.4 二级传导：DSR → 曝光（滞后 2 周）

ln(exposure_it) = 11.2 + η_i + φ_t + ω₁·dsr_i,t−2 + ω₂·dsr_i,t−3 + θ·ln(price_i) + v_it 真值： ω₁ = 0.18 DSR 每升 1 分，两周后曝光增 18%（对数半弹性） ω₂ = 0.09 三阶滞后 θ = −0.35 价格弹性 η_i ~ N(0, 0.25) SKU 固定效应 φ_t ~ N(0, 0.15) 周固定效应 v_it ~ N(0, 0.12)
关键设计意图

quality_endow（质量禀赋）同时影响退货率与曝光。这就制造了真实的遗漏变量偏差：忽略 SKU 固定效应的 Pooled OLS 会把"好货本来流量高"误读成"流量高导致退货低"，估计出的 λ₁ 出现偏误。加上 FE 后被纠正——这正是 E3 要展示的方法对比，也是"我们懂为什么用 FE"的证据。

2.5 补偿-挽单 DGP（5000 条客服记录）

诚实用户挽单概率： P_honest(c) = 1 / (1 + exp(−( b₀ + b₁·c + b₂·margin_i + b₃·complaint_history_i ))) 策略用户比例： θ(c) = θ₀ + θ₁ · c / (c + c₀) 真值： b₀ = −1.20 无补偿时挽单率约 23% b₁ = 0.055 每多补 10 元，logit 增 0.55 b₂ = 1.60 高毛利订单更易挽留（可给更多） b₃ = −0.40 历史投诉多者更难挽留 θ₀ = 0.05 基线策略用户比例 θ₁ = 0.12 最高可达 17% c₀ = 45 半饱和点（元） 观测：每条记录按 Bernoulli(P_eff(c)) 生成是否挽单

这套设定下，完整模型应估出 c* 在 ¥20–¥35 区间（视毛利档），且高毛利组 c* 明显高于低毛利组。若估计出的 c* 不在合理区间，说明模型写错了，必须回查而不是调参凑结果。

从差评到决策：让每一个补偿动作都有据可查

一、为什么选这个管理问题

电商中小商家的差评处理，长期停留在一个固定循环里：收到差评、回复道歉、发一张补偿券、等下一个差评。补偿成本持续支出，退货率却没有下降，店铺评分缓慢下滑，自然流量被平台算法一步步压低。我们在调研中接触到的商家，几乎都把差评当作"服务事件"来对待——安抚一个具体的、愤怒的人。但在几百条真实的差评文本里反复出现的，不是服务态度问题，而是产品与信息问题：版型与目标人群不匹配、详情页承诺与实物不符、包装不抗压导致破损。

归因错了，下游所有动作都会跟着错：钱花在补偿上，而不是改页面、改版型、改包装。我们想解决的不是"帮商家看懂差评"——这件事大模型已经能做——而是"帮商家把看懂变成改对，并且知道改哪一个最划算"。

二、想解决什么问题

核心问题是决策优先级。一个商家同时面对十几类问题、几十个 SKU、有限的改款预算，他需要的答案是：这个月五千块，先改哪一个？现有工具的答案是缺失的——通用 VOC 工具给出洞察报告，止步于"知道"；大模型直接分析能给出归因，但输出不稳定、无法评估准确性，商家不敢据此投入真金白银去改模具；BI 看板能展示退货率趋势，却看不出文本信号与经营结果之间的因果。三者之间缺少一个环节：从信号到决策、并且每一步都可被检验的闭环。

三、管理 Know-how

本作品的管理逻辑建立在三个非共识判断上。

第一，差评率不能直接用来排序。差评率的分母是评论数，而评论本身不是随机样本：满意用户的评论率约为 2%–5%，不满用户可达 10%–20%，遭遇严重问题的用户更高。这意味着观察到的差评率系统性高估了真实不满率，且偏差幅度随品类、促销强度、物流时效变化而不同。直接按差评率给 SKU 排优先级，排名是失真的。我们通过评分分布形状反推潜在满意度与参与率的联合分布，输出校正后的不满率排名，并与原始排名并列对比。

第二，补偿存在天花板。行业默认"多补点就能留住人"，但补偿越慷慨，越会吸引策略性投诉者——他们本不打算退货，看到补偿规则后主动制造问题。把用户分为诚实与策略两类、并让策略用户比例随补偿额上升后，目标函数出现明确拐点：超过该点，挽单率的边际提升被补偿成本与策略性损耗吃掉，利润转为下降。对低毛利 SKU，全额退款策略在数学上必然亏钱。这解释了为什么"一刀切补偿"长期看是净损失。

第三，差评是流量成本问题，不只是口碑问题。差评率上升会推高退货率，退货率压低店铺评分，评分又通过平台流量分配机制影响曝光。这条传导链若只停留在定性描述，商家不会真的行动；只有把它换算成"退货率每降一个百分点，等于每月多拿多少免费流量"，决策才会发生。

四、作品如何解决问题

作品是一个四层系统。描述层接收评论、退货原因、客服对话三类文本，通过团队自建的五域九类编码体系完成归因，输出归因看板、校正后问题排名与用户关注点分群。因果层用面板回归估计两级传导弹性，控制 SKU 与周固定效应，输出带置信区间的系数并换算为等效流量价值。决策层求解含策略性投诉的补偿最优化问题，给出按归因类型与毛利档位分层的补偿矩阵；同时把改款动作构建为带预算约束的背包问题，输出投资回报排序。证据层是贯穿始终的评测台，报告标注一致性、模型分类质量、消融结果与参数回收情况。

以一条真实差评"图片是浅灰，收到偏深几乎发黑"为例：系统判定为信息承诺类下的描述不符，置信度 0.83，证据句定位到原文，动作建议为"主图需在标准光源下重拍"，并给出该问题在同类 SKU 中的出现频次与对退货率的贡献度。商家得到的不是一句"注意色差"，而是一个可以立刻派给美工的任务。

五、千问办公承担的作用

千问办公是本作品的核心生产环境。数据接入、清洗规则配置、归因流水线编排、看板搭建、决策沙盘搭建全部在其中完成。沙盘是本作品最具交互性的部分：拖动补偿额度与改款预算两个控件，实时联动显示预计退货率、月毛利与投资回报曲线，拐点位置会随毛利档位变化而移动，让"补太多反而亏"从一个论断变成可以亲手验证的现象。所有关键任务的会话记录已留存，作为可核验依据。

六、团队进行了哪些自主设计和优化

三处核心框架由团队自主设计。其一，四级编码体系与排他规则——包括主类优先、因果链就近、色差三分法等六条判定规则，解决了"一条评论抱怨三件事"这类最常见的标注歧义。其二，双通道校验机制——大模型归因与关键词规则引擎并行判定，两路不一致的样本强制进入人工复检，使准确率从偶然结果变成可解释的工程机制，不一致率本身也成为编码体系模糊度的度量。其三，评测协议——所有通过标准在实验开始前写定并留档，避免事后挑选结果；同时设计了参数回收检验，用已知真值的模拟数据验证估计方法的可靠性。编码体系经过三个版本的迭代，每一版的修订都有标注冲突数据作为依据。
